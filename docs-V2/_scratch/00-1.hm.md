# HR-ENT-04-AUTH-PRIVACY — Coding Guide

## Mission outcome

Close:

* `HR-XCUT-P0-001` — parallel authorization entry points;
* `HR-XCUT-P0-004` — privacy port unwired and unused;
* `OPEN-DECISION-02` — authorization layering;
* `OPEN-DECISION-03` — privacy execution owner.

## The audit confirms four authorization mechanisms currently exist, while the privacy contract is defined but neither composed nor called. The canonical decision is a single contextual facade with Employee Relations as a specialized policy, plus a platform-owned privacy implementation connected through `apps/web`.

## Rules

1. Never pass a complete sensitive database row into authorization.
2. Resource context must contain only the facts needed for authorization.
3. `organizationId` must appear on both actor and resource.
4. Queries may receive a field projection.
5. Commands normally receive allow or deny only.

Every command and query must resolve to exactly one authorization classification.

  mode: HumanResourcesPolicyMode;

  resourceRequired: boolean;

  evaluate(
    request: HumanResourcesAuthorizationRequest,
    options: HumanResourcesCommandOptions,

## Registry lookup

```ts
export function resolveHumanResourcesAuthorizationPolicy(
  operationId: HumanResourcesOperationId,
  policies: readonly HumanResourcesAuthorizationPolicy[],
): HumanResourcesAuthorizationPolicy {
  const matches = policies.filter((policy) =>
    policy.operationPrefixes.some((prefix) =>
      operationId.startsWith(prefix),
    ),
  );

  if (matches.length === 0) {
    throw new Error(
      `No HR authorization policy registered for ${operationId}`,
    );
  }

  if (matches.length > 1) {
    throw new Error(
      `Ambiguous HR authorization policies for ${operationId}: ${matches
        .map((policy) => policy.id)
        .join(", ")}`,
    );
  }

  return matches[0];
}
```

Do not allow “first matching prefix wins.” Ambiguity must fail CI and fail closed.

# Slice 2.3 — Unified authorization facade

## `shared/contextual-authorization.ts`

```ts
import type { Result } from "@afenda/errors";

import type { HumanResourcesCommandOptions } from "../command-options";
import {
  HUMAN_RESOURCES_AUTHORIZATION_POLICIES,
  resolveHumanResourcesAuthorizationPolicy,
} from "./authorization-policy-registry";
import type {
  HumanResourcesAuthorizationDecision,
  HumanResourcesAuthorizationRequest,
} from "./authorization-types";

export async function authorizeHumanResourcesOperation(
  request: HumanResourcesAuthorizationRequest,
  options: HumanResourcesCommandOptions,
): Promise<Result<HumanResourcesAuthorizationDecision>> {
  /*
   * Step 1: tenant boundary.
   */
  if (
    request.resource &&
    request.resource.organizationId !== request.actor.organizationId
  ) {
    return authorizationDenied({
      policyId: "hr.tenant-boundary",
      code: "cross_tenant",
      reason: "Actor and resource belong to different organizations.",
    });
  }

  /*
   * Step 2: existing manifest permission port.
   * Replace this call with the exact existing helper name in authorization.ts.
   */
  const permissionResult = await options.authorization.authorize({
    organizationId: request.actor.organizationId,
    actorUserId: request.actor.actorUserId,
    permission: request.requiredPermission,
    operationId: request.operationId,
  });

  if (!permissionResult.ok) {
    return permissionResult;
  }

  if (!permissionResult.value.allowed) {
    return authorizationDenied({
      policyId: "hr.manifest-permission",
      code: "permission_denied",
      reason: "Required HR permission was not granted.",
    });
  }

  /*
   * Step 3: resolve exactly one contextual policy.
   */
  let policy;

  try {
    policy = resolveHumanResourcesAuthorizationPolicy(
      request.operationId,
      HUMAN_RESOURCES_AUTHORIZATION_POLICIES,
    );
  } catch (error) {
    return authorizationDenied({
      code: "policy_not_registered",
      reason:
        error instanceof Error
          ? error.message
          : "Authorization policy resolution failed.",
    });
  }

  /*
   * Step 4: fail closed where resource context is mandatory.
   */
  if (policy.resourceRequired && !request.resource) {
    return authorizationDenied({
      policyId: policy.id,
      code: "resource_context_required",
      reason: "This operation requires resource authorization context.",
    });
  }

  /*
   * Step 5: domain/contextual evaluation.
   */
  const decision = await policy.evaluate(request, options);

  if (!decision.allowed) {
    return authorizationDenied(decision);
  }

  return authorizationAllowed(decision);
}
```

`authorizationAllowed` and `authorizationDenied` should use the package’s existing `@afenda/errors` Result constructors. Do not introduce a second Result implementation.

## Denial behavior

Return the package’s canonical authorization error with structured details:

```ts
{
  humanResourcesCode: "human_resources.authorization_denied",
  operationId,
  policyId,
  denyCode,
  resourceKind,
  resourceId
}
```

Do not expose internal case membership, manager IDs or sensitive policy details in the user-facing message.

## Runner contract

```ts
export interface RunHumanResourcesOperationOptions<Input, Output> {
  operationId: HumanResourcesOperationId;
  operationKind: "command" | "query";
  requiredPermission: HumanResourcesPermission;
  input: Input;
  options: HumanResourcesCommandOptions;

  resolveResource?: (

```

## Shared runner

```ts
export async function runAuthorizedHumanResourcesOperation<Input, Output>(
  params: RunHumanResourcesOperationOptions<Input, Output>,
): Promise<Result<Output>> {
  const resource = params.resolveResource
    ? await params.resolveResource(params.input, params.options)
    : undefined;

  const authorizationResult = await authorizeHumanResourcesOperation(
    {
      operationId: params.operationId,
      operationKind: params.operationKind,
      requiredPermission: params.requiredPermission,
      actor: {
        organizationId: params.options.context.organizationId,
        actorUserId: params.options.context.actorUserId,
        actorEmployeeId: params.options.context.actorEmployeeId,
        correlationId: params.options.context.correlationId,
      },
      resource,
    },
    params.options,
  );

  if (!authorizationResult.ok) {
    return authorizationResult;
  }

  const decision = authorizationResult.value;

  if (!decision.allowed) {
    return authorizationDecisionToFailure(decision);
  }

  const result = await params.execute();

  if (!result.ok || !params.project) {
    return result;
  }

  return success(
    params.project(result.value, decision.projection),
  );
}
```

## Domain runner example

```ts
export async function runTalentCommand<Input, Output>(
  params: RunTalentCommandOptions<Input, Output>,

  return runAuthorizedHumanResourcesOperation({
    operationId: params.commandId,
    operationKind: "command",
    requiredPermission: params.permission,
    input: params.input,
    options: params.options,
    resolveResource: params.resolveResource,

  });

```

# Slice 2.5 — Employee Relations specialized policy

The existing case ACL should become a policy plugin, not be deleted. The list/get ACL and field projection are already partially aligned, so preserve that logic and register it through the facade.

## Policy adapter

```ts
// employee-relations/case-authorization-policy.ts

import {
  applyCaseFieldProjection,
  evaluateCaseReadAccess,
} from "./case-access-control";

export const employeeRelationsCasePolicy:
  HumanResourcesAuthorizationPolicy = {
    id: "hr.employee-relations.case",
    mode: "specialized",
    resourceRequired: true,

    operationPrefixes: [
      "human-resources.employee-case.",
      "human-resources.employee-case-action.",
      "human-resources.employee-case-appeal.",
    ],

    async evaluate(request, options) {
      const resource = request.resource;

      if (!resource || resource.kind !== "employee_case") {
        return {
          allowed: false,
          policyId: "hr.employee-relations.case",
          code: "resource_context_required",
          reason: "Employee-case context is required.",
        };
      }

      const access = await evaluateCaseReadAccess({
        organizationId: request.actor.organizationId,
        actorUserId: request.actor.actorUserId,
        actorEmployeeId: request.actor.actorEmployeeId,
        caseId: resource.resourceId,
        subjectEmployeeId: resource.subjectEmployeeId,
        ownerUserId: resource.ownerUserId,
        participantUserIds: resource.assignedUserIds ?? [],
        authorization: options.authorization,
        identityResolver: options.identityResolver,
      });

      if (!access.allowed) {
        return {
          allowed: false,
          policyId: "hr.employee-relations.case",
          code: "subject_scope_denied",
          reason: "The actor is not authorized to access this employee case.",
        };
      }

      return {
        allowed: true,
        policyId: "hr.employee-relations.case",
        projection: access.projection,
      };
    },
  };
```

Use the existing Employee Relations projection type if it already exists. Do not create a competing projection vocabulary.

  rawInput: unknown,

  const input = exportHumanResourcesSubjectDataSchema.parse(rawInput);

        HUMAN_RESOURCES_PERMISSION_PRIVACY_EXPORT,

        subjectPersonId: input.personId,
      },
    },

    return auth;
  }

  const privacy = requirePrivacyPort(options);

  const privacyContext = await privacy.getSubjectPrivacyContext({
    organizationId: input.organizationId,
    personId: input.personId,
    requestedBy: options.context.actorUserId,
    correlationId: options.context.correlationId,

  if (!privacyContext.ok) {
    return privacyContext;
  }

  const bundle = await collectHumanResourcesSubjectData({
    organizationId: input.organizationId,
    personId: input.personId,
    store: options.store,
    privacyContext: privacyContext.value,
    correlationId: options.context.correlationId,
  });

  if (!bundle.ok) {
    return bundle;
  }

  const recorded = await privacy.recordSubjectExport({
    organizationId: input.organizationId,
    personId: input.personId,
    requestedBy: options.context.actorUserId,
    correlationId: options.context.correlationId,
    recordCount: bundle.value.records.length,
    schemaVersion: bundle.value.schemaVersion,
  });

  if (!recorded.ok) {
    return recorded;
  }

  return bundle;
}

## Data collector

Use existing store queries. Do not introduce raw SQL into the command.

```ts
async function collectHumanResourcesSubjectData(
  input: CollectSubjectDataInput,
): Promise<Result<HumanResourcesSubjectExportBundle>> {
  const person = await input.store.findPersonById(
    input.organizationId,
    input.personId,
  );

  if (!person) {
    return humanResourcesNotFound("Person", input.personId);
  }

  const workers = await input.store.listWorkersByPersonId(
    input.organizationId,
    input.personId,
  );

  const employees = await input.store.listEmployeesByPersonId(
    input.organizationId,
    input.personId,
  );

  /*
   * Delegate each domain to a small collector.
   * This keeps the main command bounded and testable.
   */
  const records = (
    await Promise.all([
      collectIdentityPrivacyRecords(input, person, workers, employees),
      collectEmploymentPrivacyRecords(input, employees),
      collectRecruitmentPrivacyRecords(input),
      collectLeavePrivacyRecords(input, employees),
      collectTimePrivacyRecords(input, employees),
      collectCompensationPrivacyRecords(input, employees),
      collectPerformancePrivacyRecords(input, employees),
      collectLearningPrivacyRecords(input, employees),
      collectTalentPrivacyRecords(input, employees),
      collectCompliancePrivacyRecords(input, employees),
      collectEmployeeRelationsPrivacyRecords(input, employees),
    ])
  ).flat();

  return success({
    schemaVersion: "human-resources.subject-export.v1",
    organizationId: input.organizationId,
    generatedAt: new Date().toISOString(),
    correlationId: input.correlationId,
    subject: {
      personId: input.personId,
      employeeIds: employees.map((employee) => employee.id),
      workerIds: workers.map((worker) => worker.id),
    },
    records,
  });
}
```
