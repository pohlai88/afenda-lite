## Package README

`@afenda/ui-system` is Afenda-Lite's owned React component and design-token package. It gives `apps/web` one stable UI import surface for reusable primitives, common ERP display components, and semantic styling.

This README is for engineers who consume or maintain the package. Use it to choose the correct ownership boundary, import the public API, add a shadcn primitive, and run the required checks. The package requires Node `24.x`, pnpm `>=10.33.4`, React `>=19`, and Tailwind CSS `^4`.

## Understand the ERP UI baseline

The package uses one build-time metadata model rather than a runtime registry. [`src/metadata/catalog.ts`](https://github.com/pohlai88/afenda-lite/blob/main/packages/surfaces/ui-system/src/metadata/catalog.ts) is the machine-readable inventory for the locked `erp-ui-v1` baseline. It records every owned component, exact public exports, rendering boundary, capability, quality profile, required state, token family, and evidence file.

The model stays deliberately small:

| Metadata layer | Answers |
|----------------|---------|
| Component | What source and exports provide the UI, and is it client or server-compatible? |
| Capability | What reusable UI outcome exists, such as `ui.data.table` or `ui.workflow.audit`? |
| Quality profile | Which states and evidence kinds are mandatory for that class of component? |
| Surface profile | Which capabilities make a complete ERP surface such as a record editor or approval workflow? |
| Module coverage | Which predefined surface profiles each package under `packages/erp` must be able to compose? |
| Token family | Which semantic variables the capability relies on in light and dark themes? |

Component governance uses `candidate`, `approved`, `verified`, and `deprecated`: `approved` means the semantic usage contract is accepted, while `verified` means the contract is backed by the catalogue's required quality-profile evidence. Capability delivery separately uses `specified`, `implemented`, `verified`, and `deprecated`. The locked baseline fixes inventory and capability coverage; it does not automatically promote components without semantic contracts. Metadata is not exported as a browser API and does not own feature policy, permissions, persistence, transport, routes, or business schemas.

Governance is attached directly to the existing component metadata by stable `ui.*` ID. Contracts under [`src/metadata/contracts`](https://github.com/pohlai88/afenda-lite/blob/main/packages/surfaces/ui-system/src/metadata/contracts) add ownership, semantic boundaries, permitted variants and sizes, accessibility obligations, and prohibited usage without creating a second component catalogue or evidence taxonomy. Baseline evidence remains profile-derived; `governance.evidence` is reserved for additional component-specific proof.

[`manifest.contract.ts`](https://github.com/pohlai88/afenda-lite/blob/main/packages/surfaces/ui-system/src/metadata/contracts/manifest.contract.ts) is the mandatory internal authoring gateway. `defineManifestContract()` stamps `afenda.ui-component-contract/v1`, enforces non-empty canonical sections, normalizes authored clauses, and freezes the result. It does not discover or register contracts and does not own lifecycle, evidence, implementation parity, file paths, or public exports. `defineComponentContract()` defines the low-level technical shape; ordinary contract files must not call it directly.

Contract sections have distinct jobs: `componentOwns` states reusable component responsibility, `consumerOwns` states feature responsibility, and `semanticBoundaries` states interpretations or decisions the component must not imply. Rules describe correct composition; prohibited usage names concrete forbidden patterns. Contract files may be exported through the internal `src/metadata/contracts/index.ts` barrel only and must never be exported through package `src/index.ts`.

Every catalogued component now has a manifest-authored contract and remains `candidate`: complete authoring coverage does not imply semantic approval or verification. Production approval and verification require deliberate component-by-component lifecycle promotion after the applicable evidence is accepted.

Run the human-readable coverage report at any time:

```bash
pnpm --filter @afenda/ui-system metadata:report
pnpm --filter @afenda/ui-system metadata:report -- --json
```

[`__tests__/metadata-contract.test.ts`](https://github.com/pohlai88/afenda-lite/blob/main/packages/surfaces/ui-system/__tests__/metadata-contract.test.ts) compares the catalog with the real filesystem. It fails for an uncataloged component, missing source, mismatched exact export, incorrect RSC boundary, unowned package subpath, missing evidence, unknown capability, incomplete token family, or ERP module coverage drift.

### Predefined shared patterns

The baseline includes the shared patterns ERP teams otherwise tend to rebuild inconsistently:

| Concern | Shared API |

| Tabular work | `DataTable`, `ColumnVisibilityMenu`, `BulkActionBar` |

## Consume the package

`apps/web` declares this package as a workspace dependency. Import components only from the flat barrel:

```tsx
import { Button, Card, Dialog, Input, Label, cn } from "@afenda/ui-system";
```

Import the governed stylesheets once in the application's global stylesheet,
after Tailwind and animation CSS:

```css
@import "tailwindcss";
@import "@afenda/ui-system/styles.css";
@import "@afenda/ui-system/base.css";
```

Keep consumer-specific CSS after those imports. The current application entry is
[`apps/web/globals.css`](https://github.com/pohlai88/afenda-lite/blob/main/apps/web/globals.css). Do not import either
stylesheet again from individual components.

## Decide where UI belongs

| Change | Owner |
|--------|-------|
| Generic primitive or reusable interaction pattern | `packages/surfaces/ui-system` |
| Shared semantic token or theme role | `src/styles/tokens.css` |
| Feature-specific form, panel, workflow, or page composition | The owning `apps/web/features/**` area |
| Route, server action, data access, or business rule | `apps/web` or the owning domain package |
| Shadcn Studio candidate | Stage in `apps/web/shadcn-studio`, then promote owned source and prune the stage |
| Application-wide stylesheet composition | `apps/web/globals.css` |

The package is a Rank-2 Surfaces layer. It may consume client-safe platform code, but it must not import `apps/*`, server-only modules, or database code. Product code consumes this package; this package never consumes product code.

## Use semantic color roles

The theme uses the Afenda Mineral Calm foundation while retaining the owned
shadcn `new-york` component architecture. Cool-porcelain and midnight-mineral
surfaces, mineral-blue actions, ERP status, table-state, control, and focus roles
belong to one semantic theme.

| Intent | Token contract |
|--------|----------------|
| Standard surfaces and actions | Mineral Calm `canvas`, `background`, `card`, `surface-raised`, `popover`, `primary`, `secondary`, `muted`, `accent`, and sidebar pairs |
| Secondary readable copy | `foreground-secondary` or `foreground-tertiary` |
| Muted or helper copy | `muted-foreground`; its light and dark values are locked by the APCA typography contract |
| Chromatic decoration | `success`, `warning`, and `info` for icons, graphics, borders, or translucent decoration—not readable copy |
| Status text | The matching `*-subtle-foreground` role |
| Filled status UI | The complete `*-subtle`, `*-subtle-foreground`, and `*-border` triplet |

Readable pairs are tested against WCAG 2.2 AA and APCA requirements for their component typography. Focus and invalid-control indicators retain a 3:1 non-text contrast floor in both themes. Use semantic roles instead of raw color literals in component source.

## Add or update a primitive

Before adding a component, search [`src/index.ts`](https://github.com/pohlai88/afenda-lite/blob/main/packages/surfaces/ui-system/src/index.ts) and `src/components/ui` to avoid duplicating an existing capability.

1. Run the product-owned shadcn CLI from the repository root:

   ```bash
   pnpm --filter @afenda/ui-system ui:add <built-in-shadcn-name>
   ```

2. Review generated imports against [`components.json`](https://github.com/pohlai88/afenda-lite/blob/main/packages/surfaces/ui-system/components.json). Keep package-internal imports relative or on the declared `#` aliases; never point them at `apps/web`.
3. Export the public component from [`src/index.ts`](https://github.com/pohlai88/afenda-lite/blob/main/packages/surfaces/ui-system/src/index.ts). Do not add `"use client"` to the barrel; interactive components own that directive in their source files.
4. Add or update contract and interaction tests under [`__tests__/`](https://github.com/pohlai88/afenda-lite/blob/main/packages/surfaces/ui-system/__tests__).
5. Author component governance through `defineManifestContract()`, using the nearest established contract as the semantic pattern.
6. Add the component, capability, quality profile, states, token families, and evidence to [`src/metadata/catalog.ts`](https://github.com/pohlai88/afenda-lite/blob/main/packages/surfaces/ui-system/src/metadata/catalog.ts). An unregistered file is intentional drift and fails the metadata gate.
7. Run the package checks and the root integration gate shown below when validation is authorized.

`components.json` is the product CLI configuration. Keep `style: "new-york"`, `baseColor: "neutral"`, and no external `registries` entry. Shadcn Studio is a staging workflow, not an alternate package or a direct product dependency.

## Common pitfalls

- A component existing in shadcn does not automatically make it product-owned; it becomes part of Afenda only after source review, barrel export, and tests.
- Do not place feature policy in a reusable primitive. Pass state and content through a neutral component API and keep workflow decisions with the feature.
- Do not bypass semantic tokens to fix contrast locally. Correct the role or pairing and extend the contrast matrix when necessary.
- Do not add another token source of truth. `styles.css` owns values and
  `base.css` owns token-independent rendering defaults.
