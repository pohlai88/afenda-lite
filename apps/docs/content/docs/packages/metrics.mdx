## Package README

Canonical metric registry, names, labels, recording capabilities, and Prometheus exposition for Node runtimes.

## Consume

Use the explicit Node runtime capability:

```ts
import { metrics } from "@afenda/metrics/node";

metrics.record.http({
	method: "GET",
	routeTemplate: "/api/health/liveness",
	statusCode: 200,
	durationSeconds: 0.012,
});

const body = await metrics.exposition.render();
return new Response(body, {
	headers: { "Content-Type": metrics.exposition.contentType },
});
```

Database and cache adapters use `metrics.record.db` and `metrics.record.cache`. Consumers supply facts only. Metric names, label keys, service labels, buckets, registries, and Prometheus instruments remain private.

## Cardinality and tenancy

- Route labels must be static templates such as `/api/items/[id]`; URLs, queries, UUIDs, and numeric IDs are rejected.
- HTTP methods, DB/cache operations, cache results, status codes, durations, and table identifiers are bounded or validated.
- Organization, tenant, arbitrary-label, and consumer metric-name inputs are rejected at both TypeScript and runtime boundaries.
- Metrics are aggregate operational telemetry, never a tenancy data plane.

## Runtime boundary

The `/node` subpath owns the real `prom-client` implementation. Node Route Handlers must explicitly declare `runtime = "nodejs"`. No Edge no-op facade is maintained.

Type-only consumers use `@afenda/metrics/core`. Tests may use `@afenda/metrics/testing` for isolated capabilities and state reset. Production consumers that record or render metrics must use `@afenda/metrics/node`.
