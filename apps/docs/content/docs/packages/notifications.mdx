## Package README

Canonical, organization-scoped in-app notification capability for Afenda-Lite. The package owns the durable vocabulary, normalization, deduplication, persistence, expiry visibility, pagination, recipient ownership, and read-state behavior for `platform_notification`.

## Consume

Import the single root capability:

```ts
import { notifications } from "@afenda/notifications";

const result = await notifications.record({
  organizationId,
  userId,
  type: notifications.vocabulary.type.success,
  priority: notifications.vocabulary.priority.medium,
  channel: notifications.vocabulary.channel.inApp,
  title: "Role assigned",
  body: "You were assigned an organization role.",
  module: "identity",
  deduplicationKey: `event:${eventId}`,
});

const inbox = await notifications.inbox.list({ organizationId, userId });
await notifications.inbox.markRead({ organizationId, userId, id });
```

Consumers may select canonical vocabulary values. They do not import schemas, stores, Drizzle adapters, constants, or standalone persistence functions.

## Ownership

| Concern | Owner |
|---|---|
| Vocabulary, validation, normalization | `@afenda/notifications` registry |
| Write, deduplication, list, unread count, read state, deletion, purge | `notifications` capability |
| `platform_notification` table representation | `@afenda/db` |
| Event-to-notification title, body, recipient, action and metadata | Application composition root |
| HTTP and Server Action projection | `apps/web` |

`@afenda/events` must not import this package. Event handlers in `apps/web` compose events and notifications without turning either data-plane package into an orchestration layer.

## Read-state and lifecycle policy

- Records begin unread.
- Mark-one and mark-all are idempotent and constrained by organization plus recipient.
- Expired records are excluded from inbox lists and unread counts before physical purge.
- Deduplication is scoped by organization, recipient, module, and deduplication key.
- The only supported channel is `IN_APP`; no transport is claimed for EMAIL, SMS, or PUSH.
