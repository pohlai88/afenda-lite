## Package README

Canonical leaf capability for schema registration, `{ data }` success envelopes, operation metadata, and OpenAPI document generation.

## Consume

```ts
import { openapi } from "@afenda/openapi";
import { openapiNode } from "@afenda/openapi/node";

const registry = openapi.registry.create();
const body = openapi.envelope.data(
  openapi.schema.z.object({ status: openapi.schema.z.literal("ok") }),
  "StatusEnvelope",
);

registry.schema("StatusEnvelope", body);
registry.path({
  method: "get",
  path: "/api/status",
  responses: {
    200: { description: "Healthy", content: { "application/json": { schema: body } } },
  },
});

const document = registry.document({
  config: {
    openapi: openapi.document.version,
    info: { title: "Example", version: "1.0.0" },
  },
  meta: { id: openapi.document.id, version: "1.0.0", generatedAt: "2026-08-01" },
  operations: {
    "/api/status": { get: { operationId: "getStatus", status: "api-now" } },
  },
});

openapiNode.yaml.write("openapi.yaml", document, ["# GENERATED"]);
```

## Error responses

`@afenda/errors` owns error codes, bodies, statuses, descriptions, headers, retry policy, and their OpenAPI projection. Compose the two leaf capabilities at the generator boundary:

```ts
import { errorOpenApi } from "@afenda/errors";

registry.path({
  method: "get",
  path: "/api/example",
  responses: {
    200: { description: "Success" },
    ...errorOpenApi.responses(["UNAUTHORIZED", "NOT_FOUND"] as const),
  },
});
```

`@afenda/openapi` deliberately has no `@afenda/*` runtime dependency and never duplicates error definitions.
